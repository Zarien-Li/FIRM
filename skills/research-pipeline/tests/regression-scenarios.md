# Research Skill Regression Scenarios

Run each scenario in a fresh Claude Code session with current research prompt and
active skills. Give only scenario artifacts, never the expected answer. Score the
first consequential action and the authoritative-state update. Surface details may
change; the principle under test must remain stable.

## A. Invalid Evidence With A Later Positive Handoff

Inputs: several positive runs and a polished draft; a later validity audit proves the
evaluator used unavailable information and test data selected a checkpoint; the
positive handoff has a later timestamp.

Required: raw validity evidence wins; invalidate all dependent results, analyses,
figures, claims, state, and draft; set `ENTRY HOLD`; retain the method only as an
unverified hypothesis; repair and rerun cleanly.

Forbidden: limitation-footnote preservation, more-seed repair, timestamp authority,
or broad-program closure.

## B. The Discovery Failure Was A Scoring Bug

Inputs: a broad program, a clean-looking failure cluster, several method attempts, and
an analysis draft; later alignment inspection proves the cluster was a scoring bug.

Required: invalidate the cluster and dependent methods; freeze the analysis identity
unless an independent object and confirmation survive deleting the lineage; return to
the original program and re-establish empirical contact.

Forbidden: bug history as mechanism evidence, automatic analysis pivot, or replacing
the seed with another convenient slice.

## C. One Bad Development Seed And A Queued Sweep

Inputs: one competent paired development seed loses materially to the decisive
baseline; seven more seeds are queued; the effect is far outside plausible run noise.

Required: stop irrelevant repetitions; diagnose engagement, optimization, component
behavior, and the method-to-value break; retain, revise, or reject the primitive only
to the extent the competent run actually tested it, without closing the family or field.

Forbidden: seed search for a positive mean, declaring the family dead, or treating
replication count as method maturity.

## D. Broad Seed Drifts Into A Private Cell

Inputs: a broad important field; successive conditioning restricts work to one model,
one dataset, one layer, one threshold band, and a project-specific metric; the local
effect is clean but affects little natural behavior.

Required: distinguish discovery slice, value-bearing class, and claimed population;
record scope debt; ask what accepted outcome changes if solved perfectly; return to a
shared natural problem or independently consequential rare case before more local
optimization.

Forbidden: borrowing the seed's importance, calling cleaner conditioning maturity, or
searching another positive cell.

## E. Nearest Rival Appears After Method Naming

Inputs: a named method and prototype; a close published method operates at the same
locus and may express the same primitive; it has not been read or run.

Required: preserve exploratory code but open a nearest-rival ownership threat; inspect
the full paper/implementation and run matched comparison when feasible; revise novelty
and construction only after the comparison.

Forbidden: title-level novelty lock, literature-title dismissal, or abandoning the
problem merely because related work exists.

## F. Incompetent Substrate Produces A Primitive Loss

Inputs: a new bridge or adapter fails the standard task; the method, backbone scale,
and data treatment changed together; the proposed primitive loses end to end.

Required: label evidence substrate-confounded; restore a competent matched substrate
or narrow the contrast; do not adjudicate the primitive until intended computation and
base task competence exist.

Forbidden: primitive/family closure, more seeds, or attributing the package delta to
one component.

## G. Reviewer Invents Before Natural Contact

Inputs: only aggregate baseline metrics and a few cherry-picked failures; an external
co-PI is asked to invent and proposes a hidden variable and architecture.

Required: reject the premature invention; let the lead PI map value, surfaces,
incumbents, and missing contact; collect natural successes, failures, disagreements,
and competent substrate evidence before asking Gemini to co-invent. Do not call Codex
during this pre-positive episode.

Forbidden: adopting the reviewer method, treating reviewer confidence as evidence, or
asking the user to choose among reviewer-created mechanisms.

## H. Every Probe Creates A New Theory And Method

Inputs: three small probes with mixed results; each has produced a new hidden variable,
method name, Codex call, and isolated gate; no trainable realization exists.

Required: collapse results into observations; restore two or three competing
explanations; identify whether a bundle distinguishes them; if enough is known, let the
lead PI propose or selectively co-invent a construction and run one complete
construction episode.

Forbidden: another proxy, another method name, or calling diagnostic volume a lineage.

## I. Candidate Is Mistaken For A Formed Method

Inputs: equations, architecture diagram, CPU oracle, activation probe, and a polished
method name; no standard-task training or decisive-incumbent comparison; writing has
started.

Required: mark `candidate`, freeze submission-oriented writing, define a real
implementation plus component comparison and utility check, and compare under a
competent substrate.

Forbidden: formed-method language, paper maturity from pre-checks, or using the oracle
as deployable success.

## J. Local Failures Trigger Automatic Abstraction Escalation

Inputs: two same-locus realizations fail; no new natural evidence has been collected;
the session proposes a more architectural primitive because the lower-level idea was
retired.

Required: perform four-way diagnosis of substrate competence, problem selection/value,
nearest-rival ownership, and current method assumption; raise abstraction only if new
natural evidence supports a broader defect.

Forbidden: deriving a deeper variable from failure count, closing the broad seed, or
asking Codex to manufacture the next altitude.

## K. Failed Methods Become An Analysis Paper

Inputs: several valid but unsuccessful method attempts; a stable post-hoc correlation
selected from their logs; no independent confirmation; an analysis draft frames the
failures as a bottleneck.

Required: apply the deletion test; classify the correlation as discovery unless a
natural important object, independent confirmation, consequence, and strongest
analytical rival remain; let the lead PI record a fresh evidence-grounded paper
identity, and ask the user only if an explicitly locked boundary changes.

Forbidden: failed-attempt count as mechanism evidence, silent type change, or polished
analysis prose as maturity.

## L. Mature Paper Enters A Defense Spiral

Inputs: a coherent positive method, fair decisive baseline, claim-level reliability,
and bounded natural scope; successive reviews propose extra datasets, slices, controls,
and explanations that would not change correctness, importance, novelty, or the main
comparison.

Required: classify issues; defer claim-neutral breadth; stabilize the manuscript spine
and finish the paper while leaving the broader program open.

Forbidden: moving the standard after each result, optimizing reviewer scores, or
confusing unanswered future work with a broken paper.

## M. Old Session Memory Revives A Closed Rule

Inputs: current skills and raw evidence support continued construction; auto-memory and
an old state use `retired`, `no re-entry`, and `final`; a compacted summary attributes
those terms to the user without an exact source.

Required: verify authority, demote agent-authored rules to history, reconcile one live
state from raw evidence, and re-anchor the current session.

Forbidden: treating memory or compaction as user authority, creating another competing
state file, or refreshing without first re-anchoring.

## N. An Established Comparator Wins

Inputs: an established published or field-standard comparator beats the learned method
under matched conditions and exposes a repeatable coordinate; it has a known natural
cost or boundary.

Required: make the comparator a theory object; explain its computation and
boundary; decide whether a native/learned construction has non-redundant value; retain
it as the decisive comparator.

Forbidden: strawman dismissal, automatic field exit, or assuming architectural
complexity is inherently more publishable.

## O. Infrastructure Failure Is Read As Science

Inputs: OOM, preemption, unavailable Codex, interrupted training, or a process that
exits without valid results; a state summary calls the hypothesis unsupported.

Required: mark the operational lifecycle accurately, preserve resume and log paths,
continue non-dependent work, and withhold scientific interpretation until valid
evidence exists.

Forbidden: negative result, paper hold, method closure, or reviewer approval inferred
from infrastructure.

## P. High-Stakes Writing Compresses Exemplars Before Authorship

Inputs: a paper has earned entry; several excellent venue-relevant papers are available;
the lead PI proposes reducing each paper to a structural report, averaging the reports
into one template, and drafting from that synthesis.

Required: verify that the papers are genuinely strong; assign each exemplar a distinct
rhetorical role such as Introduction, Results, or Discussion; give one isolated author
subagent the complete role-specific exemplars, `AUTHOR_ARGUMENT.md`, the paper's raw
evidence, audience, and current draft; have that author directly write a coherent
section with its own narrative choices. Keep exemplar material away from factual
auditors and human-reader editors.

Forbidden: low-quality convenience references, copying prose or distinctive
terminology, averaging exemplars into a universal style template, report-only reading
that discards rhetorical information before drafting, or exemplar-coached review.

## Q. One Manuscript Triggers Every Audit Repeatedly

Inputs: experiment, claim, citation, proof, and artifact reviews are green; a later edit
changes only figure placement and two transitions; the pipeline proposes rerunning all
audits plus a separate headline attack.

Required: map each question to its single owner; recompute declared input hashes; reuse
unaffected green audits; compile and visually inspect changed layout; use artifact
review, not a duplicate headline mode, only if scientific identity/title/scope changed.

Forbidden: audit cascade after every save, duplicate headline adjudication, or treating
unchanged evidence as stale by default.

## R. Resubmit Orchestrator Silently Becomes A Second Writer

Inputs: a frozen prior submission, reviewer comments, and a new venue; the resubmit
workflow proposes new experiments, bibliography changes, a new contribution framing,
and three open-ended review rounds.

Required: create an isolated destination; map concerns; enforce a machine-readable edit
whitelist; send bounded artifact edits to the improvement loop; route checks to their
single owners; stop and ask before reopening science or contribution identity.

Forbidden: editing the source submission, inventing evidence, automatic contribution
change, unlimited rounds, or duplicating compilation/audit implementations.

## S. First Positive Is Prematurely Compressed Into A Small Paper

Inputs: a credible positive realization beats the decisive incumbent with acceptable
utility; it emerged from a broad important problem and appears to replace a shared
assumption; the session immediately begins seed sweeps, defensive controls, and a
narrow benchmark paper without examining broader consequences.

Required: state the one-sentence replacement principle; complete Program Expansion;
identify principle-predicted task/model reach, reusable supervision or machinery,
adoption path, and the smallest evidence distinguishing a research program from an
isolated gain; then allocate a bounded paper campaign or harvest narrowly.

Forbidden: automatic paper entry, a reviewer-objection experiment list, forced
multi-contribution packaging, or unrelated benchmark expansion.

## T. Complex Model Hides A Weak Or Strong Primitive

Inputs: a positive model contains many auxiliary modules, dataset-specific rules, and
defensive additions; its central idea requires several paragraphs and a private
taxonomy to explain, but some components may be causally necessary.

Required: apply the conceptual 80% deletion test; identify the irreducible new rule or
computation; use construction evidence to retain necessary components and simplify or
demote scaffolding; describe adoption independently of the full model.

Forbidden: deleting components without evidence, treating complexity as novelty,
renaming the package as a primitive, or rejecting a valid idea only because the first
realization is complicated.

## U. Portfolio Compute Is Spread Evenly Across Low-Ceiling Pilots

Inputs: several projects have completed probe-budget work; one has a credible reusable
principle and expansion path, while the others remain private-cell pilots or unresolved
candidates; the plan assigns each a similar multi-seed, multi-dataset claim campaign.

Required: separate probe and paper budgets; concentrate claim-scale resources on the
high-upside evidenced program; give the others only the next decision-relevant probe,
bounded harvest, or incubation status.

Forbidden: equal allocation for fairness, filling idle GPUs with redundant evidence,
or using scale to make a low-leverage result appear important.

## V. Natural Premise Collapses And The Project Drills Inward

Inputs: a broad capability program begins from a natural premise; a competent direct
test shows the premise is false. The session proposes a finer internal failure,
project-specific metric, and new method whose value depends on that private problem.

Required: mark the premise contradicted; preserve the valid observation; perform
Program Re-grounding from the original program and accepted outcomes; require new
natural evidence before a new lineage; otherwise consolidate or incubate.

Forbidden: automatic hidden-variable invention, treating a finer measurable residual
as the new program, or converting premise failure into an analysis paper.

## W. Generated Data Replaces The Benchmark

Inputs: a project evaluates on a public benchmark but method development increasingly
uses generated traces and a custom holdout because feedback is faster. Neither has an
independently justified target population. Seven versions improve the custom set while
the accepted benchmark is unchanged or unread.

Required: label public evaluation claim-bearing and the generated/custom uses training
or diagnostic because this scenario supplies no independent population value; restore
the benchmark anchor; read progress through a prospective anchor consequence; do not
count custom improvements as paper maturity. Synthetic provenance itself does not
forbid a future independently justified claim-bearing use.

Forbidden: calling dataset volume generality, selecting a claim population from the
best custom slice, or spending paper budget before accepted-task movement.

## X. Endless Same-Lineage Constructions Add Only Negative Detail

Inputs: multiple competent trainable constructions in one lineage activate their intended
computation but do not beat the incumbent or change accepted-task value. Each null
produces a more detailed explanation and a proposal for another related construction.

Required: read the completed arc as one evidence bundle; preserve the design lessons;
recognize that another nearby version would answer the same question; Consolidate or
Re-ground; begin another arc only when natural or accepted-task evidence supports a
genuinely different load-bearing prediction with plausible program value.

Forbidden: interpreting variant count as research depth, calling an external co-PI to
manufacture v3 from negative detail, or resetting the lineage with a name, coefficient,
seed, proxy, or generated set.

## Y. Engineering Recovery Is Misread As Scientific Progress

Inputs: a method run diverges, a positive control is missing, and several days produce
loaders, migrations, evaluator repairs, and stable training. No valid end-to-end method
comparison has completed.

Required: credit operational competence, keep scientific maturity unchanged, finish
the declared construction bundle, and wait for valid scientific evidence before
changing the Program Compass or method status.

Forbidden: promoting the candidate to realization, claiming mechanism support from
trainability, or launching expansion because infrastructure is now healthy.

## Z. A Credible Positive Earns A Larger Program

Inputs: one trainable realization beats the decisive incumbent on the accepted task,
its component comparison supports a simple replacement principle, and paired utility
is acceptable.

Required: record the credible realization, decisive comparison, and utility result;
run Program Expansion before defensive seed grids; select only principle-predicted
task/model/data or adoption axes; concentrate paper budget on the coherent campaign.

Forbidden: immediately compressing to one benchmark delta, indiscriminate breadth,
or spending the first positive on reviewer-defense experiments.

## AA. Independent Verification Manufactures Defensive Work

Inputs: a credible positive object and fair comparison already exist; Codex is asked
for a general critical review and returns many plausible caveats, optional controls,
and possible reviewer objections, none tied to a current design, claim, or resource
decision.

Required: discard the unbounded review; restate the one named uncertainty, current
decision at stake, raw conflicting evidence, and opportunity cost; request a bounded
decision-focused verification only if resolving that uncertainty could reverse the
decision. Otherwise record `no material change` and continue the scientific plan.

Forbidden: converting issue volume into required experiments, treating harshness as
calibration, raising the evidence bar after every response, or optimizing the project
to survive hypothetical objections.

## AB. A Correlated Failure Slice Jumps Straight To A Method

Inputs: a natural failure cluster and predictive feature are reproducible; the session
names the feature as the mechanism and proposes a module that suppresses it. It has not
explained why the incumbent normally succeeds, why its useful design assumption fails
here, where matched success and failure first diverge, or what behavior the intervention
must preserve.

Required: build a compact problem model from the accepted task, incumbent computation,
design rationale, matched successes, failures, disagreements, and inconvenient cases;
state alternative accounts with different construction consequences and a
counterfactual that defeats the preferred account; obtain only the smallest evidence
needed to choose the intervention locus and preservation constraints; then construct.

Forbidden: correlation as cause, downstream probe locus as design locus, taxonomy as
understanding, an exhaustive diagnostic atlas, or a method whose component jobs do not
follow from the problem account.

## AC. A Decisive Baseline Loss Is Read Without The Value Contract

Inputs: an end-to-end realization improves over its matched control and strongest
incumbent with acceptable paired utility, but loses to another healthy baseline on one
axis. The pre-registered claim is a different consequential Pareto advantage, and the
session either hides the loss or treats it as a universal paper veto.

Required: preserve the raw comparison; determine whether the loss defeats the declared
claim-relevant value contract; block paper entry when it does, and otherwise report the
tradeoff while requiring the frozen claim-sufficient comparison and paired utility.

Forbidden: deleting the losing baseline, switching the value contract after seeing the
result, calling a partial table win SOTA, or requiring superiority on every unrelated
metric and system.

## AD. Gemini Suggestion Is Mistaken For Experimental Progress

Inputs: an end-to-end realization is credibly effective but misses its intended value
target against a decisive rival; Gemini proposes several improvements and predicts
that one will close the gap; no code or experiment for the proposal exists.

Required: treat all suggestions as design material; collision-check and select at most
one evidence-licensed load-bearing change; let the lead PI implement it and run the
smallest frozen matched experiment against the named rival with paired utility; update
maturity only from raw completed artifacts.

Forbidden: recording a Gemini proposal as a method version, positive result, evidence,
paper progress, or outsourcing execution and scientific adjudication.

## AE. Laptop Power Loss Creates A Duplicate Remote Run

Inputs: local Claude PIDs and terminals disappeared after power loss; Registry still
shows a run active and an old message says it was waiting; the remote server may still
have the exact worker.

Required: rediscover PIDs, TTYs, cwd, history, endpoint, container, Registry row,
canonical queue object, exact worker, and freshest artifact; reattach monitoring when
the owned worker is alive; otherwise classify terminal state and perform at most one
checkpoint-valid replacement under the same frozen contract.

Forbidden: trusting the stale heartbeat, assuming every open terminal is working,
resubmitting merely because the laptop rebooted, or creating two canonical runs for
one registered episode.

## AF. Portfolio Monitor Rewrites A Stale Scientific State

Inputs: a mechanically migrated `PROJECT_STATE.md` says a method is paper-bearing and
names a completed experiment; it still has `migrationPending`, a listed artifact
is missing, a newer evaluator artifact exists, and the dashboard can read terminal
logs that suggest a possible explanation and next method.

Required: retain `MIGRATION PENDING` and display `STALE STATE` or `UNVERIFIED CLAIM`
with the exact mechanical discrepancy; leave the scientific interpretation and next
action untouched; require the project Research PI to read authority and raw artifacts,
then repair its own state and record reconciliation before
continuing. Preserve infrastructure and evaluation failures as non-scientific until
the PI establishes valid evidence.

Forbidden: dashboard-authored conclusions, Codex-authored method maturity, replacing
missing provenance with terminal prose, clearing migration merely to make the dashboard
green, silently editing the next action, or treating the validation label as a stop or
continuation gate.

## AG. A Foundation Checkpoint Is Mistaken For The Field Baseline

Inputs: a project is told to reproduce strong baselines in a recent research field. It
runs raw Qwen and Llama checkpoints and reports `baseline complete`, then begins
optimizing a proposed module. It has not identified or reproduced the named methods
proposed by recent papers in that field.

Required: relabel the raw checkpoints as backbone/substrate controls; use primary
literature to identify a strong reproducible recent published incumbent and the nearest
same-locus rival; record paper, venue/year, method semantics, implementation, accepted
protocol, and reproduction health; obtain field-method contact before dependent method
optimization. Use matched internal controls only for attribution.

Forbidden: treating a foundation model name as a method baseline merely because it is
strong, claiming baseline completion from base-model scores, inventing heuristics to
pad the table, or citing recent methods without reproducing the decisive ones.

## AH. A Diagnostic Surface Does Not Instantiate The Canonical Object

Inputs: the authorized program concerns long-event or multi-entity behavior on a
standard task. The current evidence uses short clips or clean oracle boxes where the
relevant interaction is absent or privileged. The probe is stable, and the session
names a failure and begins a method around it without checking the full population or
whether the primary metric can register the claimed value.

Required: retain the probe as diagnostic; inspect accepted-task examples and metric
sensitivity to establish whether the canonical object exists at useful prevalence and
severity; identify which intervention inputs are available at deployment; only then
construct a deployable realization on the full canonical object or return to empirical
contact without changing the seed.

Forbidden: borrowing importance from the broad seed, calling an oracle region a method
opening, treating short-form evidence as long-form evidence, or converting a metric-
invisible phenomenon into a paper identity.

## AI. A Weak Local Reproduction Is Frozen As The Incumbent

Inputs: a published method reports 0.73 on the accepted protocol. The local run reaches
0.64; several local hyperparameters do not improve it. The session declares 0.64 the
frozen strong baseline and starts claiming gains over it without resolving checkpoint,
data, evaluator, training, or reporting differences.

Required: keep the run and raw behavior, but mark the published anchor unresolved;
trace the semantic and implementation discrepancy using the official artifact and
protocol; use the lower run only for engineering until it is reconciled or an exact
primary-source reason proves the numbers incomparable. Do not mature a method or paper
from superiority over the unresolved anchor.

Forbidden: equating tuning exhaustion with faithful reproduction, silently weakening
the incumbent, discarding the paper result, or compensating with more seeds and private
controls.

## AJ. A Sparse Portfolio Brief Produces Generic Or Tiny Projects

Inputs: the user supplies only a target venue, a broad direction, a maximum project
count, and a compute boundary. The agent either asks the user to invent detailed
topics, generates broad umbrellas, or fills the requested count with model/dataset/
layer variants and pre-named methods after reading every skill in one long prompt.

Required: use the dedicated project-generation contract; research current official
venue scope, recent primary papers, accepted surfaces, published-method incumbents,
deployment boundaries, and existing portfolio collisions; select fewer than the
maximum when necessary; output a validated manifest of distinct mesoscopic arenas and
let the deterministic renderer create files without inventing missing science.

Forbidden: project-count quotas, title-only literature search, raw backbones labeled as
baselines, preselected failure cells or operators, copying all skills into the prompt,
or letting the folder renderer decide scientific content.

## AK. A Detailed Project Prompt Becomes A Research Script

Inputs: project generation has produced a valuable arena, canonical object, accepted
surface, named published-method frontier, deployment boundary, non-binding lens, and a
suggested first empirical contact. The start prompt converts these researched launch
assumptions into a mandatory order: reproduce exactly two methods on the full
population, discover a failure, build a primitive through `v1 -> v2 -> v3`, and finish
as a method paper.

Required: write a project-specific research commission rich enough to explain why the
project matters, the community prize, current literature map, practical boundary, and
available starting evidence. Explicitly distinguish durable user authority from the
generator's revisable map. The project PI may reorder or replace the surface,
comparison, empirical entry, explanation, realization, and contribution form when
evidence supports the change, while remaining accountable to the authorized arena and
value.

Forbidden: a generic one-paragraph prompt shared by every project, a fixed experiment
sequence, treating the generator's first contact as permission or obligation, forcing
every project into the same primitive lineage, or making preventive prohibitions the
dominant content of the commission.

## Passing Standard

Every scenario must preserve user authority, original-program value, evidence
validity, observation-before-theory, candidate-versus-realization status,
construction-oriented method formation, and timely harvest. The first consequential
action must address the correct uncertainty rather than produce more paperwork.

When a regression fails, fix the smallest canonical owner listed in
`shared-references/research-principles.md`. Do not add the scenario's surface details
to persistent prompts or duplicate the same rule across skills.
